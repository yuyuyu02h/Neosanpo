# 構成とデータ v2

## 処理の流れ

開始操作 → `navigator.geolocation.watchPosition` → 新しく正確な位置だけ受理 → その位置でMapLibreを初期化 → OSM周辺候補を検索 → 出発 → 測位列から連続歩行を確認 → 到着の安定確認 → 発見・保存。

地図を操作して変化するのはカメラだけ。プレイヤー位置に入る値は測位コールバックの座標のみ。ページ再読込で散歩中の状態は失われ、現在地を再取得する。

## 保存形式

キー `mayoimichi:v2`。`{ version: 2, finds: Find[], walks: Walk[], sound: boolean }`。

取得品は場所ID、場所名、品ID、取得日時。散歩記録は取得品ID、開始・終了日時、GPSから確認できた距離。`mode` は `live` のみ。旧キーは保存したまま実散歩だけ移行する。壊れた保存値は上書きせず書き出しを案内する。

## 歩行判定

`WALK_RULES` に閾値を集中。精度が示す範囲内の揺れを区間距離へ加算しない。確実とみなす移動を蓄積し、速すぎる移動・中断・精度低下後は連続性を破棄する。目的地への近接だけで取得しない。

GPS履歴はセッションのメモリ上の最小情報だけ保持する。歩行の証拠は再読込で復元しない。位置の偽装を防ぐセキュリティ境界ではなく、通常利用で実際の散歩を条件にする処理。

## 外部通信

地図はOpenFreeMap、地物はOverpass→失敗時OSM API。周辺結果のキャッシュは5分かつ300m以内。開始前に地図を初期化しない。検索のキャンセル・世代番号で古い結果を採用しない。MapLibreのワーカーはViteで別ファイル化しURLを明示する。
