# 構成とデータ v3.1

## 処理

利用開始 → GPS測位 → 実地図 → 道路・建物・立入制限区域の取得 → 通れる道路の接続関係を構築 → 到達可能な道路上へアイテム配置 → 最短経路表示 → 実歩行・到着の確認 → 取得・保存。

地図操作はカメラだけを変える。プレイヤーはGPSコールバックだけで更新。歩行の証拠とルートは再読込で復元しない。

| ファイル                  | 役割                                         |
| ------------------------- | -------------------------------------------- |
| src/main.ts               | 画面・GPS監視・取得・再検索・地点非表示      |
| src/map.ts                | 実地図・AI素材配置・徒歩ルート・カメラ       |
| src/navigation.ts         | 制限区域・道路の接続・経路・経路からの逸脱   |
| src/places.ts             | Overpass検索・候補配置・5分/250mのキャッシュ |
| src/walking.ts            | GPSの精度・連続歩行・到着条件                |
| src/storage.ts            | 保存・旧形式移行・破損値の保護               |
| src/items.ts / src/art.ts | 12品と個別のSVG                              |
| public/fantasy            | 配信用AIイラストWebP                         |
| assets/source-art         | 生成元PNG。静的配信の対象外                  |
| tests                     | 単体検証・ブラウザ検証・テスト専用GPS        |

## 道路と制限区域

現在地から各方向900mの矩形内の道路と、各方向1400mの制限区域、950mの建物・ゲートを取得する。円形検索より処理量を抑え、20秒・128MiBの上限を指定する。現在地を囲む大きな制限区域も `is_in` / `pivot` で取得。各地点で全ての通行規制がOSMに登録済みである保証はない。

生活道路・歩道・unclassified・tertiaryを採用し、幹線道路や小道は歩行可能なタグがあるものに限定。sidewalk=noは歩道の有無の情報として扱い、生活道路の歩行禁止と混同しない。駐車場通路・私道・条件付き通行路・高速道路は採用しない。道路上のOSMノードIDで接続し、交差して見えるだけの道は接続しない。

私有地・学校・大学等の敷地、建物、ゲートを除外。区域を横切る線分も除外し、境界との接触判定は15cmとし、敷地の外にある細い道まで削除しない。敷地の形がない学校の点は周囲250mを除外。敷地が登録済みの学校は、点からの半径を重ねない。私有のベンチ等の点は、その周りの道路まで禁止区域にしない。安全側に倒すため、通れる道まで除外する場合がある。

区域取得範囲をはみ出す道路を使わないよう、道路の両端が開始位置から900m以内の線分だけ採用する。道路の線分上を約35mごとに分割。通常は現在地から100m以内、現在地が建物・敷地に入っているときは200m以内の道路を探す。自分がいる建物・敷地だけを始点への接続判定から外し、経路と配置候補は区域外の道路に限定する。Dijkstra法で経路を求める。最寄りの道が孤立していれば、近くの別の接続道路を調べる。アイテムは経路120〜1400m、直線120m以上、候補間130m以上、最大12件。店舗や公園の中心には置かず、近くの道路の目印として名称を使う。

ルートは同じ道路網から生成し、GPSから道路までの架空の直線を足さない。道路から離れた場合は再検索を案内。通行禁止区域を通る経路や、接続できない目的地は表示しない。

## 地図描画

OpenFreeMapの実際の道路座標を保持。イラストの配置元はOverpassの完全な地物形状と `osm:way:番号` / `osm:relation:番号`。表示用地図タイルやカメラ範囲から配置を再計算しない。

`src/structures.ts` に素材一覧、変更しないv1割当枠、個別上書きを定義。IDから密度と種類を固定する。描画時の衝突判定による入れ替えを止め、地上の大きさが一定になる倍率で拡大縮小する。取得済みのIDの配置はセッション中に変更しない。再読込も同じ元データなら同じ配置になる。OSM側で地物が編集された場合の更新は、画面のズームによる変化とは別に扱う。

描画順は地形 → 建物の土台 → AIイラスト → 道路 → 徒歩ルート → 現在地とアイテム。素材名は `fantasy-` で始め、元地図のアイコン名と衝突させない。地図表示の切替後も固定配置と経路を復元する。

## 保存・通信

従来の保存キー `mayoimichi:v2` と形式を維持。別キー `neosanpo:hidden-places` は非表示の地点ID配列。非表示は端末内のみ。現在地・連続座標は永続化しない。

Overpassは主系 `overpass-api.de`、予備 `overpass.private.coffee`。両方失敗・応答不完全・区域の形が不完全なら目的地を生成しない。制限区域を確認できない代替APIへ切り替えない。検索中断・世代番号で古い結果を捨てる。一般公開APIへ大規模な負荷をかける運用は想定せず、利用者が増える場合はサーバー側キャッシュや専用の配信元を設ける。

タグの確認：[OSM sidewalk](https://wiki.openstreetmap.org/wiki/Key:sidewalk)、[OSM unclassified](https://wiki.openstreetmap.org/wiki/Tag:highway%3Dunclassified)。
